# 第三次上下文压缩前提醒

用户希望在同一会话即将第三次压缩上下文时，更换会话，减少长期开发中的信息丢失。

## 判断与提醒

- 只根据运行时明确提供的压缩事件、计数/预警或用户确认记录判断；不要把普通摘要、长回复或消息数量当成压缩事件。
- 已确认发生两次压缩，且收到下一次压缩即将发生的明确提示时，在继续新工作前提醒：“本会话即将进行第三次上下文压缩，建议现在更换会话。我会先整理交接信息，方便新会话继续。”
- 如果只能在第三次压缩之后得知，立即提醒已经发生第三次，并注明未能提前收到通知，不冒充提前提醒。
- 若运行时不暴露计数或压缩前事件，明确说明无法保证提前检测第三次；可在用户确认已发生两次时建议尽早更换，但必须区别于确定的即将压缩通知。
- 同一事件提醒一次；用户选择继续时尊重其决定，不重复打断，也不擅自结束会话。

## 交接内容

在可以写入项目文档时，将以下内容追加到 `docs/DEVELOPMENT_LOG.md` 对应日期：当前目标和已完成工作、改动文件、测试结果、未解决问题、下一步、当前分支/提交以及未提交变更概况。不要为了交接自动提交或推送。

在回复中提供一段可复制的新会话起始说明，要求新会话先阅读 `AGENTS.md`、项目介绍和开发日志，再核对 Git 状态继续。只记录有证据的压缩次数；没有证据就写“未知”。新会话从新的计数开始，不继承旧会话的次数。

不自动创建或切换会话。创建新会话需要用户明确要求；本 skill 只负责提醒和整理交接。
